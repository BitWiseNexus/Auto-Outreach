# AutoOutreach

A small Python CLI that writes and sends short, personalised cold outreach emails
to a list of company contacts, asking about open SWE / GenAI roles.

**Everything is free to run.** The emails are written by an LLM on a free tier
(Groq, with Google Gemini as an automatic fallback) and sent through your own
Gmail account over SMTP with an App Password. No paid API is used anywhere.

---

## What it does

1. Reads contacts from a CSV (`First Name, Company, Title, Email, Company Type, Salary Notes`).
2. For each contact, asks an LLM for a **subject line + body under ~120 words**,
   personalised with the company, the recipient's title, and the company type.
   The model is given only the facts in [profile.json](profile.json) and is told
   not to invent anything else.
3. Appends a fixed signature block (name + resume / GitHub / LinkedIn / portfolio
   links) that is built from `profile.json`, never generated by the model.
4. In **dry-run mode (the default)** it writes every email to `outbox/` for review.
   With `--send` it sends them one at a time, individually addressed, with a
   random delay between sends and a daily cap.
5. Every attempt is logged to a timestamped file in `logs/`, and every send is
   recorded in `sent_log.csv` so reruns skip anyone already contacted.

`Salary Notes` is deliberately **never** shown to the LLM or included in an email —
it is loaded only for your own reference.

## 1. Setup (virtual environment)

**Windows / PowerShell**

```powershell
python -m venv venv
.\venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
```

Or just run the script, which does all of the above: `.\setup.ps1`

**macOS / Linux / Git Bash**

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

Or: `bash setup.sh`

Dependencies are only `requests` and `python-dotenv` — both free and open source.
Email sending uses Python's built-in `smtplib`, so there is no mail-service SDK.

---

## 2. Get a free Groq API key (primary LLM)

1. Go to <https://console.groq.com> and sign in with Google/GitHub.
2. Open **API Keys** (<https://console.groq.com/keys>) and click **Create API Key**.
3. Copy the key (shown once) into `.env`:

```
GROQ_API_KEY=gsk_xxxxxxxxxxxxxxxxxxxx
GROQ_MODEL=llama-3.3-70b-versatile
```

The free tier has no card requirement; it is rate-limited per minute/day, which
this tool handles with backoff and a fallback.

## 3. Get a free Gemini API key (fallback LLM)

1. Go to <https://aistudio.google.com/apikey> and sign in with a Google account.
2. Click **Create API key** and copy it into `.env`:

```
GEMINI_API_KEY=AIza...
GEMINI_MODEL=gemini-2.0-flash
```

If Groq errors, rate-limits or returns unusable output, the tool automatically
retries and then falls back to Gemini. Either key alone is enough to run, but
having both means a rate limit never stops a batch.

## 4. Create a Gmail App Password (free sending)

An App Password is a 16-character password Google issues for a single app. It is
free and works with any normal Gmail account.

1. Turn on **2-Step Verification**: <https://myaccount.google.com/signinoptions/two-step-verification>
   (App Passwords are unavailable without it.)
2. Go to <https://myaccount.google.com/apppasswords>.
3. Type any app name (e.g. `AutoOutreach`) and click **Create**.
4. Copy the 16-character password shown (e.g. `abcd efgh ijkl mnop`) into `.env`.
   Spaces are stripped automatically, so paste it either way.

```
GMAIL_ADDRESS=you@gmail.com
GMAIL_APP_PASSWORD=abcdefghijklmnop
SENDER_NAME=Aditya Rehpade
```

Your normal Gmail password will **not** work — Google blocks it for SMTP.

> Note on Google Workspace / school accounts: if `apppasswords` says the option
> isn't available, the admin has disabled it. Use a personal `@gmail.com` account.

## 5. Run it

Always activate the venv first (`.\venv\Scripts\Activate.ps1` or `source venv/bin/activate`).

**Dry run — generates everything, sends nothing (this is the default):**

```bash
python main.py --dry-run
python main.py --dry-run --limit 3        # just the first 3, to sample the tone
```

Output lands in `outbox/<timestamp>/`:
one `.txt` per contact for easy reading, plus `emails.json` with everything.
Read a few before you send.

**Sanity check — send exactly one generated email to yourself:**

```bash
python main.py --test
```

It uses the first eligible contact as the sample, prefixes the subject with
`[TEST]`, and sends only to `TEST_RECIPIENT` (or your `GMAIL_ADDRESS`).
The real contact is not emailed, and nothing is written to `sent_log.csv`.

**Send for real:**

```bash
python main.py --send                     # asks for confirmation first
python main.py --send --limit 10          # send only 10 this run
python main.py --send --yes               # skip the confirmation prompt
```

**Other flags**

| Flag | Meaning |
|---|---|
| `--csv PATH` | Use a different contacts file (default: `companies.csv`) |
| `--limit N` | Process at most N contacts this run |
| `--delay-min` / `--delay-max` | Override the pause between sends (seconds) |
| `--daily-cap N` | Override the per-day send cap |
| `--resend` | Don't skip contacts already marked SENT |
| `--verbose` | Print each generated email to the console |

## Safety and deliverability

These defaults exist to keep your Gmail account healthy and your mail out of spam:

- **One email per contact, individually addressed.** Never CC/BCC in a batch.
- **Random delay between sends**, `SEND_DELAY_MIN`–`SEND_DELAY_MAX` (default 45–60s).
- **Daily cap**, `DAILY_SEND_CAP` (default 40). The count is taken from today's
  `SENT` rows in `sent_log.csv`, so it holds across multiple runs in a day. When
  the cap is hit the run stops cleanly; run it again tomorrow to continue.
- **Reruns never double-send.** Anyone with a `SENT` row is skipped.
- **Addresses are validated** before sending; malformed rows are skipped and logged
  with their CSV row number. Duplicate addresses in the CSV are skipped too.
- **Every attempt is logged** to `logs/autooutreach_<timestamp>.log` with the
  outcome and, on failure, the reason.
- Ctrl+C mid-run is safe: everything already sent is recorded before the exit.

Gmail's own limit for a personal account is ~500 messages/day, but cold outreach
should stay far below that — 40/day is a deliberately conservative default.

## Files

| File | Purpose |
|---|---|
| [main.py](main.py) | CLI, run modes, orchestration, logging |
| [config.py](config.py) | Loads `.env` + `profile.json`, validates settings |
| [llm.py](llm.py) | Prompting, Groq → Gemini fallback, retry/backoff, output sanitising |
| [mailer.py](mailer.py) | Gmail SMTP, address validation, message building |
| [tracker.py](tracker.py) | CSV loading, `sent_log.csv` read/write, daily-cap counting |
| [profile.json](profile.json) | The only facts the LLM may use about you — edit freely |
| [.env.example](.env.example) | Every setting, documented; copy to `.env` |
| `outbox/` | Dry-run output (git-ignored) |
| `logs/` | Per-run logs (git-ignored) |
| `sent_log.csv` | Send history: Email, Status, SentAt, Subject, Provider, Error (git-ignored) |

Editing your background, links or target roles is a `profile.json` change — no
prompt text needs touching. Tone and structure rules live in `SYSTEM_PROMPT` in
[llm.py](llm.py).

## Cost

Nothing here costs money:

| Step | Service | Cost |
|---|---|---|
| Email writing | Groq free tier | Free (rate-limited) |
| Fallback writing | Gemini free tier | Free (rate-limited) |
| Sending | Gmail SMTP + App Password | Free |
| Tracking / logging | Local CSV + log files | Free |

The one place a paid service would normally appear is bulk sending — SendGrid,
Mailgun, SES, Postmark. This tool deliberately avoids all of them; `mailer.py`
uses stdlib `smtplib` against Gmail, which is fine at this volume. If you ever
outgrow ~40 emails/day, that's the module to swap.

## Troubleshooting

| Symptom | Fix |
|---|---|
| `No LLM key configured` | Fill `GROQ_API_KEY` and/or `GEMINI_API_KEY` in `.env` |
| `Gmail rejected the login` | Use a 16-char **App Password**, not your Gmail password; check 2FA is on |
| `Missing GMAIL_ADDRESS...` | Fill the Gmail section of `.env` (only needed for `--send` / `--test`) |
| `Daily cap reached` | Expected — rerun tomorrow, or raise `--daily-cap` |
| `is missing column(s) for: ...` | Your CSV headers don't match; the required columns are First Name, Company, Title, Email, Company Type |
| Emails read too generic | Tweak `SYSTEM_PROMPT` in [llm.py](llm.py), or add detail to `profile.json`, then re-run `--dry-run` |
